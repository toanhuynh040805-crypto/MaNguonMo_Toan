# GỢI Ý PHÂN CÔNG NHÓM

Quy định môn học yêu cầu **3–5 sinh viên**, có minh chứng phân công công việc rõ ràng. Điền tên/MSSV của người thực hiện thực tế, không ghi thành tích không có.

## Phân công cho nhóm 3 người

| Thành viên (điền tên) | Phụ trách | Minh chứng |
|---|---|---|
| Thành viên 1 | Phân tích yêu cầu, ERD, Migration, Model, Seeder, CRUD danh mục/sản phẩm | Migration, `CategoryController`, `ProductController`, commit Git |
| Thành viên 2 | Giao diện Blade/Bootstrap, trang chủ, tìm kiếm, giỏ hàng, responsive | `resources/views`, CSS, ảnh chụp demo, commit Git |
| Thành viên 3 | Đăng nhập/phân quyền, checkout, đơn hàng, test và tích hợp | Auth, Middleware, Checkout, Order, kiểm thử, commit Git |

**Cả nhóm:** thống nhất CSDL, review code chéo, test end-to-end, làm báo cáo và demo. Không nên giao một người làm toàn bộ dự án trong khi báo cáo ghi cả nhóm cùng triển khai.

## Nhóm 4–5 người

- **Người 4:** viết test, tổng hợp kết quả thực nghiệm, hỗ trợ quản lý đơn và dashboard.
- **Người 5:** hoàn thiện báo cáo, sơ đồ và trình bày (vẫn cần tham gia code hoặc test để có đóng góp kỹ thuật).

## Quản lý công việc

Tạo các issue/commit theo phần việc, nêu rõ người thực hiện và kết quả. GitHub có thể dùng để lưu bằng chứng lịch sử thay đổi. Trước buổi bảo vệ, mỗi thành viên nên tự chạy và trình bày được phần mình phụ trách.
